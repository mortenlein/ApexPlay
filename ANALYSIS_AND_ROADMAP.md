# ApexPlay — Full Project Analysis & Roadmap

_Audit date: 2026-06-27_

ApexPlay is a Next.js 14 (App Router) + Prisma/SQLite platform for running CS2 (and other team-esport) tournaments: organizer creates a tournament, players sign in with Steam and register teams, brackets are generated and advanced, and live state is pushed to an OBS overlay and a marshal/admin view. A CounterStrikeSharp plugin + webhook receiver feeds live match data.

**Intended product flow (the thing to optimize for):**
Organizer creates tournament → players Steam-login → register via form → invite teammates by link → sign-up complete → matches follow a schedule → each team sees its place in the queue → teams get notified when it's their turn → admin advances the bracket.

The codebase **mostly works** for a single-admin LAN/Docker deployment, but it has accumulated real security problems, an architecture that contradicts its own deploy config, advertised features that don't actually work, heavy information-architecture sprawl, and an inconsistent/unfinished design system. Two of the core flow steps (queue visibility, notifications) are not built.

> _Note on origin: this app was generated by Gemini in the Antigravity IDE, which explains the sprawl and inconsistency. The sibling project **`subtick`** (`/home/mole/subtick`) is the reference for how to do deploy/auth cleanly._

---

## 0. Decisions locked + Phase 0 status

**Decisions (2026-06-27):**
- **Deploy target = Docker self-host only.** Netlify path removed.
- **Admin = identity, seeded via `.env`** (the subtick model): a Steam user whose steamid64 is in `ADMIN_STEAMIDS` is admin. No shared password.

**What subtick does (the pattern we adopted):**
- `ADMIN_STEAMID(S)` in `.env` → resolves to admin at login; everyone else is a player (reads open, writes 403).
- `docker-compose.yml` uses `${VAR:?msg}` so the stack **won't boot** with a required secret unset — nothing hardcoded.
- `.env.example` template tracked; real `.env` git-ignored; secret generated with `openssl rand -hex 32`.
- Auth URLs built from a `PUBLIC_URL`/`NEXTAUTH_URL` env, never from request headers.

**✅ Phase 0 done on branch `phase0-security-docker`** (typecheck passes, not yet committed):
- Removed hardcoded `"Tjarb123"`; deleted the entire shared-password admin system (`admin-session.ts`, `/api/auth/login`, password helpers in `auth.ts`).
- Added `src/lib/admin-config.ts` (edge-safe `ADMIN_STEAMIDS` allowlist); `isAdminAuthenticated()` + `middleware.ts` now check the Steam identity. `/login` is now Steam sign-in (+ dev mock personas). _(closes C1, H1, H2 core)_
- Webhook auth is now **mandatory / fail-closed** in both `cs2` and `matchzy` routes. _(part of H3)_
- `docker-compose.yml` rewritten with fail-fast required env + `ADMIN_STEAMIDS`; added `.env.example`. _(C1, H5)_
- Removed `netlify.toml` (Docker is the target) and the empty duplicate `tailwind.config.js`. _(C2 deploy side, M2)_
- Untracked 73 build artifacts + loose dev scripts/reports; `.gitignore` updated. _(M3)_
- Migrated the two e2e specs + Playwright config off password login to the mock-persona admin identity.

**✅ H3 done (webhook match resolution):** Both `cs2` and `matchzy` webhooks now resolve a match *deterministically* — trusted explicit `matchId`, else a single unambiguous match within an explicit tournament. Removed the "most recent LIVE match" global fallback and the `includes("team")/("tba")` fuzzy heuristic that could rewrite an unrelated match. Team-name auto-sync now only runs on `matchId`-resolved matches and only over placeholder names (never clobbers an organizer-set name).

**✅ C3 done (real double elimination):** `generateDoubleElimination` builds a full winners + losers bracket and a single grand final, unit-tested (`npm run test:bracket`) for 4/8/16/32 teams (correct match counts, no dangling/duplicate/self links, every non-seeded slot fed exactly once). The generate route now branches on `format`, rejects non-power-of-two DE with a clear message (instead of silently building single-elim), and routes winners/losers across WINNERS/LOSERS/GRAND_FINAL via new explicit `nextMatchSlot`/`loserNextMatchSlot` columns. Both advancement paths (manual update + CS2 webhook) honor those slots, falling back to the `matchOrder % 2` parity rule so single-elim is byte-for-byte unchanged. _v1 limitations (documented): power-of-two only, single-match grand final (no bracket reset), losers bracket is BO1._

**Still open from Phase 0 follow-ups:** roles beyond admin/player (H1 full), the redesign (M1/M2), the missing player features (H4), **EON broadcast-HUD support** (GSI-direct: generate the GSI cfg + serve match metadata), DE bracket-reset + byes, and a double-elim bracket *visual* in the UI.

## 2. Redesign direction (UX + visual)

The current design fails on two axes: **information architecture** (too many overlapping homes) and **visual coherence** (a documented theme that doesn't match the implemented one). Recommended approach:

**A. Collapse to three clear surfaces, by role**
1. **Public / Spectator** (`/t/[id]`) — bracket, schedule, live scores, rosters, OBS overlay. No login.
2. **Player** (`/me`) — Steam login → my tournaments, register, team invite link, **my place in the queue**, notifications/"you're up next". This is the flow the owner described and is currently the weakest surface.
3. **Control** (`/control` for admin + marshal, with real roles) — create/manage tournaments, generate/advance brackets, load matches, marshal seat/check-in view.

Retire `/dashboard` vs `/admin` vs `/tournaments` vs `/marshal/dashboard` in favor of the above; keep redirects from old URLs.

**B. One real design system**
- Pick the actual product identity (esports, dark-first) and make `globals.css` tokens the single source of truth. Delete `tailwind.config.js`, fold the real tokens into `tailwind.config.ts`, and rewrite `design.md` to describe *this* system (the current HashiCorp doc is misleading).
- Define a small component kit (Button, Card, Input, Badge/StatusPill, Table, Modal, EmptyState, Toast) so pages stop hand-rolling styles. Many already exist as `.mds-*` utility classes — promote them to real components.
- Finish (or explicitly drop) light mode; right now it's a stub.
- Establish a typographic + spacing scale and a status-color language (LIVE / pending / done / bye) used consistently across bracket, overlay, queue, and tables.

**C. Player-flow polish (the headline UX)**
- Registration as a guided 1-screen form (team name, logo, size) → instant invite link with copy/share + QR for LAN.
- A live "Your match" card: opponent, map, **N matches ahead / est. wait**, station/seat, and a clear "GO TO YOUR STATION" state when called.
- Notifications: start with web-push (PWA) + the existing Discord path; the in-app live state already has the SSE backbone (once C2 is resolved).

## 3. Roadmap

### Phase 0 — Stop the bleeding (security & hygiene) — ~1–2 days
- [ ] Remove hardcoded password from `auth.ts`; require `ADMIN_PASSWORD` + `ADMIN_SESSION_SECRET` (fail closed if missing). _(C1, H2)_
- [ ] Rotate/clear the committed secrets in `docker-compose.yml`; move to `.env`/`.env.example`. Scrub from history if the repo is/was shared. _(C1)_
- [ ] Make webhook auth **mandatory** (`CS2_WEBHOOK_KEY` required) and key/lock the `matches/[id]/config` endpoint. _(H3, M4)_
- [ ] `git rm -r --cached` all `bin/`,`obj/` artifacts and loose dev scripts; add to `.gitignore`. _(M3)_
- [ ] Delete empty `tailwind.config.js`. _(M2/Low)_

### Phase 1 — Decide the platform shape — ~2–3 days
- [ ] **Commit to one deploy target.** For a LAN/self-host tool: keep Docker + standalone, **remove `netlify.toml`** (or replace the in-memory bus with a real one if you truly need serverless). _(C2, H5)_
- [ ] If staying self-hosted but wanting multi-instance/reliability later: plan a move off SQLite (Postgres) and adopt Prisma **migrations** instead of `db push`. _(M6)_
- [ ] Replace the in-process `eventBus` with something durable enough for the chosen target (single-process is fine for one Docker container — just document and enforce it). _(C2)_

### Phase 2 — Correctness of the core domain — ~3–5 days
- [ ] Implement real **double elimination** in `bracket-utils` (losers bracket + grand final), or remove the option from the wizard until it's real. _(C3)_
- [ ] Harden webhook match resolution: require explicit `matchId`/`tournamentId`, drop the "any LIVE match" + fuzzy-name fallback that can mutate the wrong match. _(H3)_
- [ ] Add unit tests for seeding, BYE propagation, and bracket advancement. _(M5)_

### Phase 3 — Roles & accountability — ~3–4 days
- [ ] Real roles (organizer/admin/marshal) tied to Steam/Discord users instead of one shared password; record actor identity in `AuditLog`. _(H1)_
- [ ] Scope admin APIs to the acting user's tournaments.

### Phase 4 — Redesign & IA consolidation — ~1–2 weeks
- [ ] Build the design-system component kit + token cleanup; rewrite `design.md`. _(M2)_
- [ ] Collapse routes into Public / Player / Control; add redirects from legacy paths. _(M1)_
- [ ] Unify the two client data layers (`lib/api.ts` + `lib/client-api.ts`) and remove ad-hoc `fetch` in components. _(M5)_

### Phase 5 — Finish the player flow — ~1 week
- [ ] **Queue view**: "you are N matches away," seat/station, est. wait, live state. _(H4)_
- [ ] **Notifications**: PWA web-push + Discord DM/announce for "match starting / you're up." _(H4)_
- [ ] Registration UX polish (invite link + QR, team-full/dup handling already solid in `signup/route.ts`).
